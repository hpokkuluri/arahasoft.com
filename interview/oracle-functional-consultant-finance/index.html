1What is the difference between Oracle E-Business Suite and Oracle Fusion Cloud ERP?Fusion BasicsBasicTop question

Why they ask: a basic question, but it shows whether you understand how the work changes.

Answer:

"EBS is on-premise or hosted. The customer owns the database, applies patches, and can customize code directly. It has a Forms UI, concurrent programs and responsibilities. Fusion Cloud ERP is SaaS: Oracle hosts it and upgrades it every quarter. There's no direct database access, so we extend through configuration, Visual Builder, OIC, BI Publisher and REST APIs. It has a browser UI, scheduled processes and role-based security. For a consultant, setups are done through Functional Setup Manager tasks, every quarterly update needs regression testing, and reporting uses OTBI, BI Publisher and Financial Reporting or Smart View."

Tip: If you've worked on both, give one task you did in each. It proves the experience.

Likely follow-up

What does the quarterly update cycle mean for a consultant?

Every quarter Oracle pushes an update, so we read the release notes, test the key flows — journal entry, invoice-to-pay, receipt application — in a non-production pod about two weeks before production, and switch on new features deliberately. Regression testing becomes a routine part of support, ideally automated, not a one-off project.

2What is Functional Setup Manager and how do you use it?Fusion BasicsBasic

Why they ask: FSM is how every Fusion setup is done.

Answer:

"FSM is the Fusion tool for all application setup. Offerings, like Financials, contain functional areas, like Payables, which contain setup tasks, like Manage Payables Options. You opt in to the offerings and features you need and work through the task list. Implementation projects group tasks so you can assign them and track status. Configuration packages export setups from one environment and import them into another, like test to production. And scope values let you set up a task for a specific BU or ledger."

Tip: Mention configuration packages. It shows you know how setups move between environments.

Likely follow-up

What's the difference between an offering and a functional area?

An offering is a broad product like Financials; functional areas are parts of it, like Payables or Assets. You opt in to both, and only opted-in areas show their setup tasks.

3What are the "4 Cs" of a ledger in Oracle?General LedgerBasicTop question

Why they ask: a basic question that every Oracle Financials consultant should answer quickly.

Answer:

"A ledger is defined by four things: the chart of accounts, which is the account structure; the calendar, which defines the periods, like monthly or 4-4-5; the currency; and the accounting method, which is the Subledger Accounting method that tells subledgers how to create journals. Two legal entities can share a primary ledger only if all four are the same. If any one differs, they need separate ledgers."

Tip: Add the rule about sharing a ledger. It turns a definition into a design point.

Likely follow-up

Which of the four Cs can two ledgers in a ledger set differ on?

Currency. Ledgers in a ledger set must share the same chart of accounts and accounting calendar, but they can have different currencies — for example a US ledger in USD and a UK ledger in GBP in one set, so you can open and close periods and run reports across both at once.

4What is a balancing segment and why is it important?General LedgerBasicTop question

Why they ask: balancing segments drive entity reporting and intercompany.

Answer:

"The balancing segment is the chart of accounts segment, usually company, for which Oracle makes sure debits equal credits on every journal. If a journal crosses two balancing values, say company 101 and 102, Oracle adds intercompany balancing lines automatically using the intercompany rules. Balancing values are usually assigned to legal entities, so you can produce a balance sheet for each entity. Fusion supports up to three balancing segments, for example company and cost center, if the business needs a balance sheet at that level too."

Tip: Mention the three balancing segments. It's a Fusion detail that shows current knowledge.

Likely follow-up

What happens if you have two companies but only one balancing segment value?

You can't produce a balanced balance sheet for each company, because Oracle only forces debits and credits to balance by balancing segment value. Each legal entity needs its own balancing values; otherwise intercompany entries net out inside one value and you lose the separate trial balance per company.

5Walk me through the life of a manual journal entry in Fusion GL.General LedgerBasicTop question

Why they ask: a basic GL question that shows whether you know the controls along the way.

Answer:

"It starts with creating the journal, either on the Create Journal page or by uploading the ADFdi spreadsheet, with batch, journal, ledger, period, category and lines. As lines are entered, cross-validation rules check every account combination and reject invalid ones. If journal approval is on for that source, it routes through the BPM rules, usually by amount. Once approved, it's posted, either by hand or by AutoPost, and posting updates the balances and the cube. If it's an accrual, it's set to reverse automatically in the next period."

Tip: Mention the spreadsheet upload. Most finance teams enter journals that way, and it shows you've worked with them.

Likely follow-up

What stops a user from posting their own large journal?

Journal approval rules — for example any journal over $50,000, or any journal touching cash or revenue accounts, routes to the controller before posting. Add segregation of duties so the preparer role can't approve or post its own entries, and review the posted-journal audit report at month end.

6What are cross-validation rules?General LedgerBasic

Why they ask: a basic COA control that every GL consultant sets up.

Answer:

"Cross-validation rules stop invalid combinations of segment values from being created. For example, 'balance sheet accounts, 1000 to 3999, must use cost center 000'. Each rule has a condition filter, which says when it applies, a validation filter, which says what's allowed, and an error message the user sees. One thing to know: they only stop new combinations. Combinations that already exist have to be disabled separately. So I set them up before transactions start, and test them with real account strings."

Tip: Make the point that they only block new combinations. It's the follow-up question.

Likely follow-up

What's the difference between cross-validation rules and segment value security?

Cross-validation stops invalid combinations from being created for anyone. Segment value security restricts which values specific users can use.

7How do you open and close GL periods, and what statuses can a period have?General LedgerBasic

Why they ask: a basic close question.

Answer:

"The statuses are Never Opened, Future Enterable, Open, Closed and Permanently Closed. I open the next period in Manage Accounting Periods or with the Open Period process. In a Future Enterable period, journals can be entered but not posted. I close the period once all subledgers have transferred and all journals are posted and reconciled. A Closed period can be reopened; Permanently Closed can't, so I only use it after audit sign-off. Subledgers like AP, AR and Assets have their own periods, and they close before GL."

Tip: Explain when you'd use Permanently Closed. It shows care with irreversible steps.

Likely follow-up

Why use Future Enterable status?

It lets users enter journals for next period, like accruals, without opening it for posting. They post once the period opens.

8What is the difference between a primary ledger, a secondary ledger and a reporting currency?General LedgerIn-depthTop question

Why they ask: a core design question.

Answer:

"The primary ledger is the main book of record for a legal entity. A secondary ledger is a parallel ledger that can differ in chart of accounts, calendar, currency or accounting method. It's used for local GAAP vs IFRS or US GAAP, or for a different statutory chart, and it can be kept at subledger, journal or balance level. A reporting currency has the same chart, calendar and method as the primary; only the currency is different. So my rule of thumb: if only the currency differs, it's a reporting currency; if anything else differs, it's a secondary ledger."

Tip: Give the rule of thumb. It answers the question in one sentence.

Likely follow-up

When would you use a reporting currency instead of a secondary ledger?

When only the currency differs. A reporting currency is a copy of the primary ledger's balances or journals converted to another currency, like EUR for a parent. If the chart of accounts, calendar or accounting method differs — say IFRS versus US GAAP — you need a secondary ledger instead.

9Explain revaluation and translation in GL.General LedgerIn-depth

Why they ask: people often confuse the two.

Answer:

"Revaluation adjusts foreign-currency balances to the period-end rate. For example, a EUR bank account in a USD ledger is revalued, and the difference goes to unrealized gain or loss, usually reversed next period. Translation converts the whole ledger's balances into another currency for reporting or consolidation: balance sheet at the period-end rate, P&L at the average rate, equity at historical rates, and the difference goes to CTA. Revaluation comes first, after all foreign-currency transactions are posted, then translation."

Tip: State the order: revalue, then translate. It's what they want to hear.

Likely follow-up

Where does unrealized gain from revaluation get reversed?

Revaluation journals are usually set to reverse at the start of the next period, so the following month revalues fresh from the original balances.

10How would you set up a recurring allocation, for example rent allocated by headcount?General LedgerIn-depth

Why they ask: a practical allocation question.

Answer:

"In Fusion I'd build it as a Calculation Manager allocation rule. The source, or pool, is the rent account balance for the period. The basis is a statistical account holding headcount by cost center, loaded every month from HR. The target is rent expense on each receiving cost center, in proportion to headcount. The offset is a credit back to the source cost center. It generates each month, on a schedule or by hand, and someone reviews it before posting. In EBS the equivalent is MassAllocations. I test it first with a small set of numbers I can check by hand."

Tip: Mention testing with numbers you can check by hand. It shows care with allocations.

Likely follow-up

What happens if headcount isn't updated before the allocation runs?

Rent goes out on last month's headcount, so departments are charged wrongly. The statistical load is a close checklist step before allocations.

11Explain the Procure-to-Pay flow and where AP fits in.Accounts PayableBasicTop question

Why they ask: a basic question, but they listen for whether you connect the steps to the accounting.

Answer:

"Procurement starts it: a requisition becomes a purchase order. Receiving records the goods or services. Then AP takes over: the invoice is entered or imported and matched to the PO and receipt, validation checks matching, tax and holds, the invoice is approved, and it is paid through a payment process request. Finally Create Accounting sends the entries to the General Ledger through Subledger Accounting."

Worked example: the entries for a $1,000 purchase

  • Receipt: Dr Inventory or Expense 1,000 / Cr Receipt Accrual 1,000
  • Invoice: Dr Receipt Accrual 1,000 / Cr AP Liability 1,000
  • Payment: Dr AP Liability 1,000 / Cr Cash Clearing 1,000
  • Bank reconciliation: Dr Cash Clearing 1,000 / Cr Cash 1,000

Tip: Walking through the four entries without being asked separates a finance consultant from a system user.

Likely follow-up

What happens in GL when a PO receipt is entered?

With receipt accrual on, Oracle books Dr Expense or Inventory, Cr Receipt Accrual when goods are received. When the AP invoice is matched and accounted, it books Dr Receipt Accrual, Cr Supplier Liability. So for a $1,000 receipt, the accrual sits at $1,000 until the invoice clears it to zero.

12What is the difference between 2-way, 3-way and 4-way matching?Accounts PayableBasic

Why they ask: a core control question. They want the definitions and when you would use each one.

Answer:

"It's how many documents the invoice must agree with before it can be paid. Two-way checks the invoice against the PO, quantity and price, which suits services or low-risk items. Three-way adds the receipt, so we only pay for what was actually received. Four-way adds inspection or acceptance, used where quality checks matter, like lab supplies or parts that can be rejected. The match level is set on the PO schedule, defaulted from the supplier, item or purchasing options. Anything outside tolerance goes on hold."

Example: PO for 100 units at $10. Receipt for 90. Invoice for 100 at $10.

  • 2-way: passes (invoice agrees with the PO).
  • 3-way: quantity received hold, because only 90 were received.

Tip: The worked example shows you understand the control, not just the terms.

Likely follow-up

Where do you set which matching level a PO uses?

On the PO schedule, defaulted from the item, supplier or purchasing options, with values like two-way or three-way.

13What are invoice holds and how do you release them?Accounts PayableBasicTop question

Why they ask: holds drive most AP work, and how you handle them shows if you understand the controls.

Answer:

"A hold stops an invoice from being paid until something is fixed. The common ones are matching holds like quantity ordered, quantity received, price and amount; variance holds on distributions or tax; account holds for an invalid account; supplier or site holds; and manual holds placed by users. System holds release on their own once the cause is fixed and the invoice is validated again, for example after the goods are received or the PO price is corrected. Manual-releasable holds need an authorized user to release them with a reason. To keep holds moving, I route each type to its owner with the holds resolution workflow."

  • Matching: quantity ordered, quantity received, price, amount.
  • Variance: distribution or tax variance.
  • Account: invalid distribution account.
  • Supplier or site: payment hold.
  • Manual: placed by users.

Tip: Stress that you fix the cause, not just release the hold. Releasing holds without fixing them is an audit finding.

Likely follow-up

Who should release a price hold?

The buyer, because they own the PO price. If the invoice says $10.50 and the PO says $10, the buyer either confirms the supplier is right and updates the PO, or tells AP to short-pay or get a credit memo. AP shouldn't force-release price holds on its own.

14What types of invoices can you enter in Payables?Accounts PayableBasic

Why they ask: a foundation check. A wrong invoice type means wrong accounting or reporting.

Answer:

"The everyday one is the standard invoice. Credit memos are credits from the supplier, debit memos are credits we raise against the supplier ourselves. Prepayments are advances that get applied to invoices later. Withholding tax invoices are created automatically for amounts withheld. Expense reports come in from Oracle Expenses for employee reimbursement. Payment requests pay people who aren't suppliers, like customer refunds. And interest invoices are created automatically for late-payment interest if that's set up."

  • Standard, Credit memo, Debit memo
  • Prepayment
  • Withholding tax (system-created)
  • Expense report (from Expenses)
  • Payment request (non-supplier payees)
  • Interest (system-created)

Tip: Mention the difference between a credit memo and a debit memo clearly. Many candidates mix them up.

Likely follow-up

When would you use a debit memo instead of waiting for a credit memo?

When we've agreed a credit with the supplier, like for returned goods, and want to record it immediately rather than wait for their paperwork.

15How does a prepayment work in AP?Accounts PayableBasic

Why they ask: prepayments touch the balance sheet, and unapplied prepayments are a classic audit issue.

Answer:

"First you enter a prepayment invoice, validate it and pay it. That books a prepaid asset instead of an expense. When the real invoice arrives, you apply the prepayment to it, which reduces what you still owe and moves the amount out of the prepaid account. Temporary prepayments are meant to be applied to invoices. Permanent ones, like a lease deposit, are not. Oracle can also apply prepayments automatically during validation if that's set up. At month-end, I reconcile the prepaid account so nothing sits unapplied."

Worked example: $5,000 advance, then a $12,000 invoice

  • Prepayment invoice: Dr Prepaid Expense 5,000 / Cr AP Liability 5,000
  • Payment: Dr AP Liability 5,000 / Cr Cash 5,000
  • Apply to the $12,000 invoice: Dr Expense 12,000 / Cr AP Liability 7,000 / Cr Prepaid Expense 5,000

Tip: Mention reconciling the prepaid account. Unapplied prepayments are a common audit question.

Likely follow-up

Why can't you pay a prepayment-applied invoice for the full amount?

Applying the prepayment reduces the amount due, so only the net is paid and the prepaid asset is relieved.

16What is a Payment Process Request (PPR)?Accounts PayableBasicTop question

Why they ask: every payment in Fusion goes through a PPR, so you need to explain it clearly.

Answer:

"A PPR is how Fusion selects invoices and pays them in bulk. You give it selection criteria: pay-through date, business unit, supplier, payment method, pay group and currency. Then the payment and processing options: which bank account, which payment process profile, and whether to stop for review. It runs in steps: select the invoices, review the proposed payments, build the payments, create the payment file or print checks, and transmit to the bank. Most companies schedule them, for example a daily ACH run and a weekly check run. The payment process profile decides the file format, such as NACHA or ISO 20022, and how it's sent."

  1. Select invoices.
  2. Review proposed payments (optional stop).
  3. Build payments.
  4. Create the payment file or print checks.
  5. Transmit to the bank.

Tip: Mention scheduled PPR templates. Real companies don't submit PPRs by hand every day.

Likely follow-up

What do you review before confirming a PPR?

The proposed payments: total amount against cash available, any unusually large payments, new or changed supplier bank accounts, suppliers on hold and duplicate amounts. Once the PPR is confirmed and the file is formatted and sent, a change means voiding payments, so this review is the last cheap control point.

17How do you handle 1099 reporting in Oracle Payables?Accounts PayableIn-depth

Why they ask: 1099 errors cost penalties and go straight to the IRS. They want to see you start long before January.

Answer:

"It starts with supplier setup: US suppliers who need 1099s are marked federal reportable, with their taxpayer ID and income tax type, for example NEC for services. That income tax type defaults onto invoice distributions. During the year, if suppliers were set up wrong, I fix the history with the Update and Report Income Tax Details process. At year-end I run the US 1099 Report, the Invoice Exceptions and Supplier Exceptions reports, and then produce the electronic file or the printed forms."

  • Setup: federal reportable, taxpayer ID, income tax type (NEC, MISC).
  • During the year: Update and Report Income Tax Details for corrections.
  • Year-end: US 1099 Report, exception reports, 1099 Electronic Media.

Tip: Say you review the exception reports in December, not January. It shows you've been through a real year-end.

Likely follow-up

What if a supplier's 1099 type was wrong all year?

Update the supplier, then run the Update Income Tax Details process to correct historical invoice distributions before running the 1099 reports.

18Explain the Order-to-Cash flow and where AR fits in.Accounts ReceivableBasicTop question

Why they ask: a warm-up question for every finance or O2C role.

Answer:

"It starts with the customer set up with an account and bill-to and ship-to sites. Sales books an order in Order Management and the warehouse ships it. The shipment flows to AR through AutoInvoice and becomes an invoice. The customer pays, and we record the receipt manually, through lockbox, or from the bank statement, then apply it to the invoice. Anything unpaid goes to collections. Finally Create Accounting sends the entries to GL. AR owns the middle of that chain: invoicing, cash application and collections."

Accounting:

  • Invoice: Dr Receivable, Cr Revenue, Cr Tax.
  • Receipt: Dr Cash, Cr Receivable.

Tip: Give the two journal entries at the end. It shows you think like an accountant, not only a system user.

Likely follow-up

What links a shipped order to an AR invoice?

When the order line ships, fulfillment sends the billing data — customer, item, quantity, price and the order reference — into the AutoInvoice interface. AutoInvoice then creates the invoice using the transaction source and transaction type, and the order number is kept as a reference so you can trace invoice back to order.

19What is AutoInvoice?Accounts ReceivableBasic

Why they ask: AutoInvoice is the main way invoices get into AR. Every AR interview touches it.

Answer:

"AutoInvoice is the program that imports billing lines from other systems and turns them into invoices, credit memos and debit memos. In Fusion the lines come from Order Management, Projects, or a file through FBDI; in EBS they go into RA_INTERFACE_LINES_ALL. The transaction source controls validation and defaults. Grouping rules decide which lines become one invoice, and line ordering rules sort them. AutoAccounting, together with SLA in Fusion, derives the revenue and receivable accounts. Lines that fail stay in the interface with an error, and you fix them and resubmit. On a busy project it's normal to process tens of thousands of lines a night, so the error handling is as important as the setup."

Tip: Cover source, grouping, accounting and errors. Those are the four follow-up questions they'll ask.

Likely follow-up

What's the most common AutoInvoice failure?

Invalid or inactive customer sites or accounts, followed by missing accounting setup or invalid items.

20What is the customer structure in Oracle (party, account, site)?Accounts ReceivableBasic

Why they ask: a basic question, but bad customer data causes most AR errors, so they want to see you understand the model.

Answer:

"Oracle uses the Trading Community Architecture. The party is the real company or person, say ACME Corp. The customer account is our business relationship with that party, with terms, a profile and credit settings, and one party can have several accounts, for example one for ACME's US business and one for Canada. Each account has sites, which are addresses, and each site has site uses, like bill-to and ship-to. The customer profile carries the credit limit, collector, statement and dunning settings. Because the party is shared, the same company can be both a customer and a supplier."

  • Party: the real-world entity.
  • Account: the relationship (terms, credit).
  • Site and site use: the address and what it's for.
  • Profile: credit, collector, dunning.

Tip: Give the one-party-two-accounts example. It shows you've designed customer data, not just entered it.

Likely follow-up

Why can one party have multiple customer accounts?

Different business relationships, like a parent buying from two divisions with different terms or currencies.

21How do you apply a receipt, and what happens with unapplied or on-account cash?Accounts ReceivableBasicTop question

Why they ask: cash application is core AR work. They want to hear the different states of cash and why they matter.

Answer:

"I create the receipt against a receipt method and bank account, manually, from lockbox or from the bank statement, then apply it to one or more open invoices. If it covers only part, the invoice stays open for the rest. Any money I can't match yet is unapplied: we know the customer but not which invoices. On-account is a deliberate choice to leave the money on the customer's account, like a deposit or an overpayment we'll use later. Unidentified means we don't even know the customer yet. In Fusion, AutoMatch uses the remittance details to apply receipts automatically, so people only work the exceptions."

  • Unapplied: customer known, invoices not yet.
  • On-account: parked on purpose.
  • Unidentified: customer unknown.

Tip: Explaining the three states cleanly is the whole answer. Add that you'd watch the unapplied balance every week.

Likely follow-up

What's the difference between unapplied and on-account cash?

Unapplied is cash we've received but haven't matched to anything yet — usually because we don't know which invoice it's for. On-account is a deliberate choice to hold the cash as a customer credit to use later, like a deposit. Unapplied should be worked down daily; on-account is a known balance.

22What is the difference between an adjustment and a credit memo?Accounts ReceivableBasic

Why they ask: people often mix these up. The right choice affects revenue, tax and what the customer sees.

Answer:

"A credit memo corrects the billing. It's a transaction document, usually sent to the customer, and it reverses revenue and tax, for example for a return or a pricing error. An adjustment changes the invoice balance without saying the billing was wrong, for small write-offs, bad debt or rounding. It uses a receivables activity for the GL account and is limited by the user's approval limit. So if we billed $1,000 but should have billed $900, that's a credit memo. If we billed correctly but the customer paid $998 and we won't chase $2, that's an adjustment."

Tip: The rule of thumb: billing was wrong → credit memo; the money won't be collected → adjustment. Say it in one line.

Likely follow-up

Why not use adjustments to fix pricing errors?

Adjustments don't reverse revenue and tax properly or produce a customer document, so pricing errors should be credit memos.

23How does an asset get created from an AP invoice?Fixed AssetsBasicTop question

Why they ask: a basic question, but it covers the most common path into Assets.

Answer:

"AP charges the invoice line to an asset clearing account, or flags it Track as Asset. After the invoice is validated and accounted, Create Mass Additions sends the line to the Mass Additions queue in Assets. There, someone reviews it: assigns the category, location, cost center and date placed in service, and merges or splits lines if needed. Then Post Mass Additions creates the asset. Depreciation starts based on the date placed in service and the prorate convention."

Tip: Keep it as five clear steps. It's a process question, so answer it as one.

Likely follow-up

What's a common reason an asset never gets created?

The invoice line was charged to a regular expense account instead of the asset clearing account, so Create Mass Additions never picks it up. I'd check the distribution account, and make sure the PO or the invoice defaults to the clearing account for capital items above the threshold, say $5,000.

24What are the main asset transactions in Oracle Assets?Fixed AssetsBasic

Why they ask: a basic question to check you know the asset life cycle.

Answer:

"An addition creates the asset. An adjustment changes its cost, life or method. A transfer moves it to another location, cost center or employee. A reclassification changes its category. A retirement removes it, fully or partly, with proceeds of sale and cost of removal, and Oracle calculates the gain or loss. A reinstatement undoes a retirement in the same period. Where the accounting standard requires it, there's also revaluation and impairment. Every one of these creates accounting through SLA after Create Accounting."

Tip: Follow the life of an asset from birth to retirement. It's easier to remember and to listen to.

Likely follow-up

Which of those transactions changes depreciation expense account?

A transfer to a new cost center, because the expense account comes from the asset assignment.

25What is depreciation prorate convention?Fixed AssetsIn-depth

Why they ask: prorate conventions explain why first-month depreciation looks wrong to new users.

Answer:

"The prorate convention decides when depreciation starts, based on the date placed in service. With following month, an asset added on March 10 starts depreciating in April. With mid-month, it gets half a month in March. With actual month, it gets a full month in March. With half-year, common in US tax books, it gets half a year of depreciation in the first year no matter which month it was added. The convention is set on the category for each book and defaults to the asset."

Tip: Use one date and walk it through each convention. It makes the answer easy to follow.

Likely follow-up

How does convention affect year-one depreciation?

It changes how many months are depreciated in the first year, so an asset placed in December might get one month or none depending on the convention.

26How does bank statement reconciliation work in Oracle Cash Management?Cash ManagementBasic

Why they ask: the core Cash Management question.

Answer:

"Statements are loaded from bank files like BAI2, MT940 or CAMT.053, or entered by hand. Autoreconciliation then matches statement lines to AP payments, AR receipts and journals using the reconciliation rule set, on reference, amount and date within tolerances. Whatever doesn't match, I reconcile manually. For lines that are just bank fees or interest, transaction creation rules create external transactions automatically. When a payment is reconciled, Fusion books Dr Cash Clearing, Cr Cash, and that goes to GL."

Tip: Mention the clearing entry at the end. It shows you know reconciliation drives accounting.

Likely follow-up

What's a good autoreconciliation rate to aim for?

Above 90%. Below that, I look for patterns like bank fees or batch deposits to fix with rules.

27What is the difference between a bank, a branch and a bank account in Oracle?Cash ManagementBasic

Why they ask: a basic setup question.

Answer:

"The bank is the institution, like JPMorgan Chase. The branch is a specific branch with its routing number or BIC. The bank account is our company's account at that branch, with the account number, currency, cash and cash clearing GL accounts, and its uses, like Payables, Receivables or Payroll. A bank account is owned by a legal entity and can be used by the business units that are given access to it."

Tip: Mention legal entity ownership. It's the part that drives intercompany questions later.

Likely follow-up

Who owns the bank account in Fusion?

A legal entity, and business units are then granted access to use it for payables or receivables.

28What is Create Accounting and why does it matter?Subledger AccountingBasicTop question

Why they ask: a basic question for anyone working in Fusion finance.

Answer:

"Subledger transactions, like invoices, receipts and asset additions, don't reach GL by themselves. Create Accounting runs Subledger Accounting to build the journal entries from those events, and can then transfer and post them to GL. It runs in draft, which you can review and change, or final, which is locked. Errors, like an invalid account, show up in the execution report, and you fix them and rerun. I schedule it daily rather than only at month-end, so problems surface early instead of on the last day of close."

Tip: Say "daily, not month-end". It's the practical point that shows experience.

Likely follow-up

What's the difference between Create Accounting in draft and final?

Draft accounting creates entries you can review but doesn't send anything to GL, and you can rerun it after fixing data. Final accounting locks the entries, so the transaction can't change, and can transfer and post to GL. Most period-end runs are final; draft is for checking first.

29How do you find out why a transaction did not create accounting?Subledger AccountingIn-depthTop question

Why they ask: a common support question with a clear method.

Answer:

"I check the Create Accounting execution report for the error, and the transaction's accounting status, for example an invoice showing Unaccounted. The common causes are: the transaction isn't validated or approved; the subledger period is closed; the account combination is invalid or disabled; a cross-validation rule failed; or a mapping set has no value for this case. Review Subledger Journal Entries shows any draft entries with errors. Once I fix the cause, I rerun Create Accounting for that transaction or batch."

Tip: Give the list of causes in the order you'd check them. It's the method they want.

Likely follow-up

62What happens when you retire an asset?Fixed AssetsIn-depth
